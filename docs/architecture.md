# Forza Telemetry Stream Deck プラグイン 機能・アーキテクチャ設計書

本ドキュメントは、Forza Horizonのテレメトリデータ（"Data Out"）を受信し、Elgato Stream Deck + に表示するプラグインの機能仕様およびシステム設計（アーキテクチャ）について解説します。

---

## 1. アクション機能仕様（ユーザーインターフェースレイヤー）

本プラグインでは、液晶キー用の `Keypad` デバイスと、ダイヤルおよびタッチスクリーン用の `Encoder` デバイスの特性を活かした3つのアクションを提供します。

### 1.1 速度計（Speed Meter）
* **デバイス割り当て**: `Encoder`（ダイヤル）専用アクション
* **表示項目・描画ロジック**：
  * **デジタル速度表示**： タッチスクリーン（液晶ディスプレイ）右側に 55pt の巨大デジタルフォントで表示。プロパティインスペクタの設定で「KM/H」と「MPH」の切り替えが可能。
  * **現在のギア表示**： 画面左側に緑色の円枠（`◯`）とギア文字（R, 1, 2...）で大きく描画。Forza Horizon 6 の実車仕様（通常のニュートラルギアはなく、`0 = Reverse`、`1 = 1速`、`2 = 2速`...）に完全に適合。
  * **RPMレベルバー**： ディスプレイ下部（Y: 80〜95）に配置。エンジンの最高回転数に対する現在のRPM割合を0〜100%で表示。70%以上で黄、85%以上で赤（レブリミット）に自動色変化。
* **UI安定化設計（チャタリング防止）**：
  * クラッチを踏まないシフトチェンジ時などに送信される、瞬間的な動力未伝達／ギア抜けの状態を示す特殊値（テレメトリ値 `11`）を無効値 `null` として検知し、画面上には直前の有効なギア表示を維持し続けることで、UIの不快なチラつきを排除するバッファリング処理を搭載。

### 1.2 ラップタイム（Lap Time）
* **デバイス割り当て**: `Encoder`（ダイヤル）専用アクション
* **表示項目・描画ロジック**：
  * **LAP情報・順位**： 画面上部に「LAP X」（テレメトリ値 `lapNumber + 1`）と「POS Y」（`racePosition`）を左右均等に配置。
  * **現在ラップタイム**： 中央に「CUR」ラベルと現在のラップタイムを「分:秒.ミリ秒」形式で大きく描画。
  * **比較用ラップタイム**： 下部にサブラベルと数値（自己ベストまたは前周ラップタイム）を表示。
* **インタラクション**：
  * ダイヤルプッシュ（Dial Down）または液晶ディスプレイタップ（Touch Tap）により、比較用のタイムを「BEST（自己ベストラップ）」と「LAST（前周のラップタイム）」で交互にトグル切り替え。
* **ステート（キャッシュ）維持設計**：
  * 画面切り替え（WillAppear/WillDisappear）時も、直前のデータを削除せず Map 内にキャッシュとして保持し、画面復帰時に即座にデータを再現するUX設計。

### 1.3 Gフォースメーター（G-Force Meter）
* **デバイス割り当て**: `Keypad`（液晶キー）および `Encoder`（ダイヤル）の両方にハイブリッド対応
* **表示項目・描画ロジック**：
  * **Gボールプロット**： 中央の十字破線と同心円状のガイドラインに対し、現在の前後左右の慣性Gフォースを白いドット（Gボール）でリアルタイムにプロット。最大スケールを超える場合は境界円上に自動クランプ。
  * **ピークGドット**： 走行中に発生した最大の合成Gの位置を半透明の黄色いドットとして画面上に維持。
  * **最大合成G・現在G数値**： 液晶ディスプレイのみ、右上に最大合成G（黄文字）と、右下に現在の合成G（白文字）をリアルタイムに描画。
  * **現在のスケール**： 液晶ディスプレイのみ、左下に現在の表示スケール上限（例：「2.0G」）を表示。
* **インタラクション（共通基底クラスの活用）**：
  * `PressDurationAction` 基底クラスを活用し、キーとダイヤルの両方の押し下げイベントを共通ハンドリング。
  * **短押し（キー押下 / ダイヤルプッシュ）**： 表示スケールをトグル切り替え（1.0G／2.0G／3.0G）。
  * **長押し（キー押下 / ダイヤルプッシュ、500ms判定）**： ピークG値をリセット。リセット成功時には一瞬「RESET」と緑色のテキストで画面中央に表示されるフィードバックを表示。
* **アセット一貫性（ベストプラクティス適合）**：
  * 液晶キーの静的アイコンとソースコードの動的描画デザインを統一するため、白（`#FFFFFF`）の太線のみ・背景透過のミニマルなモノクロアイコン（`icon.png`, `icon@2x.png`, `key.png`, `key@2x.png`）を適用。
* **ステート（キャッシュ）維持設計**：
  * 画面切り替え時もピークGなどのデータをクリアせず保持し続けることでステートを維持。

## 2. システムアーキテクチャ（インフラレイヤー）

### 2.1 プラグイン初期化とライフサイクル（`src/plugin.ts`）
* **起動シーケンス**： `streamDeck.connect()` による Stream Deck 接続完了後、グローバル設定（ポート、IPアドレス）を `getGlobalSettings` を通じて非同期にロードし、UDP 受信サーバーの初期バインドを実行。
* **リアルタイム設定同期**： `onDidReceiveGlobalSettings` イベントをフックし、ユーザーが設定画面でバインドポートやアドレスを変更した際に、動的かつシームレスにサーバー設定に反映。
* **ログ管理**： 開発・デバッグ時のトレーサビリティを確保するため、開発用のログレベル `trace` を有効化。

### 2.2 設定バリデーション（`src/settings/settings.ts`）
* **セキュリティ・クラッシュ防止設計**： `node:net` の `net.isIPv4` と数値範囲チェックを活用した、ポート（0〜65535）およびアドレスのバリデーション処理。無効な設定値（例：不正なIP文字列、無効なポート範囲）が入力された場合のバインド失敗によるプラグインクラッシュを防止。

### 2.3 UDP テレメトリサーバー（`src/telemetry/server.ts`）
* **ソケット通信のバインド**： `node:dgram` による `udp4` ソケット通信を実装。
* **安全なバインド制御**： 同一設定による不要なサーバーの重複起動を防ぐ二重バインド防止機能、およびエラー・切断検知時の自動的なソケットクローズ・再試行処理などの例外リカバリ機構を搭載。

### 2.4 テレメトリ配信マネージャー（`src/telemetry/manager.ts`）
* **シングルトン保証**： リソース重複を避けるため、シングルトンパターンによる単一の `telemetryManager` インスタンスからデータソースを一元配信。
* **スロットリング配信制御**： 描画およびシリアル通信負荷を最小限に抑えるため、テレメトリデータの配信頻度を最大 20FPS（50ms 間隔）に制限。
* **動的なリソースクリーン（省電力設計）**： `data` イベントのリスナー数（`listenerCount`）を監視。
  * リスナーが 0 から 1 になったとき（アクションが画面上に現れたとき）： 自動的に UDP サーバーを起動。
  * リスナーが 1 から 0 になったとき（すべてのアクションが消えたとき）： `process.nextTick` を利用して非同期にサーバーを自動停止し、不要なポート占有とCPUリソース消費を解放。
